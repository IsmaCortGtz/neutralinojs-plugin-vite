# Building & Distribution

`neu vite build` produces a distributable app in one step: it runs your frontend's production build and then bundles the NeutralinoJS binaries around it.

```bash
cd my-app          # NeutralinoJS project root
neu vite build
```

## What it does

The command is equivalent to:

```bash
cd vite-src/
<package-manager> run build    # the "build" script from the Vite package.json
cd ..
neu build
```

with two practical differences:

- The Vite `build` script is **read and executed directly** — no package-manager binary is invoked, and the project's `node_modules/.bin` is put on `PATH`. It behaves identically whether you use npm, pnpm, yarn or bun.
- Everything runs in one command with consistent error propagation (a failing frontend build stops before bundling).

The result lands in the distribution directory (`dist/` by default, or whatever `cli.distributionPath` points to), containing the platform binaries plus your built assets.

## Flags

| Flag | Description |
|---|---|
| `-r, --release` | Also generate a release ZIP |
| `--embed-resources` | Embed resources into the binaries |
| `--copy-storage` | Copy `.storage` into the bundle |
| `--macos-bundle` | Create macOS app bundles (`.app`) |
| `--clean` | Delete previous files from the distribution directory first |
| `--config-file <path>` | Use an alternative configuration file |

Requirements checked before building:

1. The config file (`neutralino.config.json`, or `--config-file`) exists in the current directory.
2. `cli.vite.projectPath` is set ([integration guide](./existing-project.md)).
3. That directory's `package.json` defines a `"build"` script.

## Compatibility with neutralinojs-builder

[neutralinojs-builder](https://github.com/neutralinojs-community/neutralinojs-builder) is a separate community plugin that generates platform-specific installers from the output of a NeutralinoJS build. This plugin is compatible with it: since `neu vite build` ends with the standard NeutralinoJS bundling step, the builder can pick up its artifacts right after — no extra configuration needed.

```bash
# 1. Install it once
neu plugins --add @neutralinojs-contrib/builder
```

```bash
# 2. Build the app, then package it for your target
neu vite build
neu builder nsis       # Windows .exe installer
```

Available targets:

| Command | Output |
|---|---|
| `neu builder nsis` | NSIS installer (Windows x64) |
| `neu builder deb` | Debian package (GNU/Linux) |
| `neu builder appimage` | AppImage (GNU/Linux x64) |
| `neu builder dmg` | DMG installer (macOS) |

> [!IMPORTANT]
> Always run `neu builder <target>` **after** `neu vite build`: the builder works on the artifacts generated by the NeutralinoJS bundling step.

A full release pipeline looks like:

```bash
neu vite build -r      # frontend + native bundle + release zip
neu builder deb        # repeat per target as needed
```
